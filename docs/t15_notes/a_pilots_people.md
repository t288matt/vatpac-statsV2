# T15 notes: pilots and people cards (180, 181, 182, 175, 183, 155)

Written 08-10-2026. Source: the owner's Metabase export (SQL text only). All times UTC. No migration was needed: every panel wraps `flight` in a CTE named `flight_summaries`, so the v1 SQL stays almost word for word.

## v1 to v3 column mapping (applies to every card here)

| v1 `flight_summaries` column | v3 source | Difference |
|---|---|---|
| `cid`, `name`, `logon_time` | `flight.cid`, `flight.name`, `flight.logon_time` | `logon_time` is the session logon, so every flight part of a session shares it. |
| `completion_time` | `flight.end_time` | v1 set it when a flight completed (after the v1 completion window); v3 has the last stored position for every flight, including one still online, so a pilot who is online now already appears. |
| `total_enroute_time_minutes` | `flight.airborne_minutes` | Repo-wide assumption (also cards 93, 135): enroute = airborne (groundspeed of 60 kt or more, 40 s gap cap). Not confirmed with the owner (T14 question 4). v3 values are smaller or different from v1 and not comparable. NULL when the raw positions were removed by retention. |
| `time_online_minutes` | `flight.duration_minutes` | v3 = first to last stored position inside the Australian polygon. v1 may have counted from logon. Hours will be lower than v1 for flights that connected outside the polygon. |
| one row per flight | one row per `flight` row (session, gap segment, 8 h part) | A long session can be several flights. Sessions without a filed departure and arrival are not flights in v3 (the flight gate), so pilots who never filed a plan are invisible; v1 also gated at ingest (ADR-007), so the effect should be similar. |
| Y rule | kept verbatim on `name` | The fourth character from the end of the name is `Y`. Not the same as v3 `home_icao` / `pilot_is_local`: it also matches names such as "Joe Yoda" and misses a pilot whose name ends in a lower-case or non-Y airport. See question 1. |
| `DATE_TRUNC('month', ts)` | `DATE_TRUNC('month', ts AT TIME ZONE 'UTC')` | Explicit UTC, so the buckets do not depend on the database session time zone. Month columns are `timestamp` (no zone), which Grafana reads as UTC. |

## Owner questions (needs owner input)

1. Y rule. v1 uses the fourth character from the end of the pilot's name (a home-airport suffix such as ICAO starting with Y). It is kept exactly. Should v3 instead use `home_icao` (a trailing four-letter token that passes `icao_is_home`), which avoids false matches such as a name ending in "Yoda" but would change the counts (a pilot whose name has no airport suffix would never count)?
2. Card 180 and 181: should a pilot with no filed flight plan count as "logged on but never flew"? v3 cannot see them (the flight gate) and v1 probably could not either (ADR-007). Confirming means no change; saying yes needs a new view over `pilot_session` and a new decision.
3. In-progress flights. v1 only used completed flights (`completion_time IS NOT NULL`). In v3 a pilot who has just logged on and has not yet moved appears as "never flew" for up to the whole current session. Should flights seen in the last 15 minutes be excluded?
4. Hours basis (cards 183 and 155). v1 `time_online_minutes` is probably logon to completion; v3 uses time inside the polygon. Is that acceptable, or should it be logon to last sighting? (Same as the open question 4 in T14 about what enroute time means.)
5. Card 155: the title says "most time online" but v1 sums enroute minutes of flights over 30 minutes. Keep as is, or change to online time?
