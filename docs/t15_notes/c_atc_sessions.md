## Not verified

- No Postgres was available, so the integration tests and every new query are unexecuted. The author ran only the static checks (dashboard validator with sqlglot, column check, ruff, py_compile, the non-integration suite). The coordinator needs to run `tests/integration/test_atc_sessions_t15.py`. Highest-risk construct: the `RANGE ... interval FOLLOWING` window frame on a timestamptz column in card 186 (supported by PostgreSQL 11 and later).
- Card 186 cost on a large `controller_session` table is untested; the range filter is what keeps it bounded.

## Panel notes

- Names and CIDs are shown in all five panels (ADR-009, ADR-019).
- `controller_summaries` runs the merged-session window functions over the whole table before filtering; at current volumes this is cheap, but check the query plan if the table grows large.
