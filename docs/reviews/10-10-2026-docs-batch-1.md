## Findings, ranked

1. CHANGELOG.md lines 13 and 23: "merged 10-10-2026 09:42, merge commit d0ceaaa" and "09:51, merge commit acc55db". Neither is a merge commit: d0ceaaa and acc55db are the docs commits that tipped the branches (one parent each; the branches were fast-forwarded onto main). The times are git local times (+01:00, BST), so in UTC they are 08:42 and 08:51, but the page says times are UTC. Correct text: "(merged 10-10-2026 about 08:42 UTC, branch tip d0ceaaa ...)" and "(about 08:51 UTC, branch tip acc55db ...)". Line 92 should say the merge times are git commit times converted to UTC.
2. IF_CLAUDE_IS_UNAVAILABLE.md line 72: "Never boot a restored copy of the v1 clone VM on the LAN." Ambiguous. VM 100 (the v3 VM) is a clone of the v1 box; OWNER_ACTIONS.md item 3 says to remove the network device from the restored scratch copy. Suggested text: "When you test-restore the Proxmox backup of this VM, remove its network device before starting it (it is a clone of the v1 machine and would clash on the LAN); steps in OWNER_ACTIONS.md item 3."
3. IF_CLAUDE_IS_UNAVAILABLE.md lines 80-93: after deploy 1, `restore.sh` refuses a dump whose newest poll data is more than 48 h older than the dump's file-name time (RESTORE_MAX_POLL_AGE_HOURS, restore.md). A cold reader restoring after a long outage would hit a refusal the card does not mention. Add: "If it refuses because the dump is stale and you know why, ask for help or see restore.md (RESTORE_MAX_POLL_AGE_HOURS=0)." (The deployed version has no such check, so this only matters after deploy 1.)
4. IF_CLAUDE_IS_UNAVAILABLE.md line 91 (B4): `docker compose up -d` brings the stopped collector back without `--build`, which section 4 says never to do. Harmless here (no code change, the image exists), but say so: "(no code change, so no build is needed)". Also `make restore`/`make backup` use `docker compose exec` without `-T`, so run them in an interactive ssh session, not as `ssh vatpac-v3 'make ...'` (not run; compose exec needs a TTY).
5. Low: the deployed ops/smoke.sh contains `DELETE FROM poll_log` as `grafana_ro` (issue #86, fixed in fix-ops, not deployed). It deletes only if grants are wrong, which is not the state after a restore (restore drops ACLs, so grants are absent until `migrate` runs; migrate is step 3 before smoke in B4). Safe as written; keep the step order.
6. Low: the card names the owner's local PC path (C:\Users\mdora\...) and the VM user name; not secrets.
7. Low, README.md section 6 first row: cites "RESUME.md line 41" as saying the heartbeat files "arrive on main from the branch owner-actions"; confirmed true (wording is on line 41), fine.
