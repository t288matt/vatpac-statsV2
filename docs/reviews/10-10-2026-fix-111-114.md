## Findings (ranked)

**F1 (medium, same class as #114): `parse_frequency_hz` still raises on a huge exponent.**
`collector/src/vatpac/model.py:86` catches `(InvalidOperation, ValueError, OverflowError)`. `Decimal("1e999999") * 1_000_000`
raises `decimal.Overflow` (an `ArithmeticError`, neither of the three). Reproduced: `parse_frequency_hz("1e999999")` and
`"1E+999999999"` raise. Caller `collector/src/vatpac/store.py:226` runs inside `apply_snapshot`, outside the per-entry
`parse_all` try, so one controller with `"frequency": "1e999999"` (a 9-character string, well inside the 2000 cap) fails the
whole snapshot write on every poll while it stays in the feed. Fix: catch `ArithmeticError` (covers `decimal.DecimalException`
and `OverflowError`) or `decimal.DecimalException`, and add `"1e999999"` to the invalid-frequency cases. `inf`, `Infinity`,
`-Infinity`, `-inf`, `nan` are correctly None.

**F2 (low, accepted behaviour): prefix collisions.** Two callsigns equal over their first 500 bytes merge into one session
(`x*600+"A"` and `x*600+"B"` both cut to the same string). Real callsigns are at most 7 bytes (fixtures), departure and arrival
at most 4, so no real session is affected; the merge only affects abusive input and is deterministic (a replay maps the same way).
Cut happens after `_callsign` normalisation, so identity for normal data is unchanged.

**F3 (low): a ProgramLimitExceeded cause that is not row-specific** (class 54: too many columns or arguments, statement too
complex) would reject every row singly, each logged and counted in `rejected_values`; the snapshot would store nothing, but it
is visible (warning per row, counter). Index-row-too-large and jsonb-too-large are the real cases and are handled by the
bisect. The `CheckViolation` re-raise guard is untouched. Acceptable.

**F4 (info): lone surrogates.** `cap_text` uses `surrogatepass` so a lone surrogate counts as 3 bytes; when a cut falls after
one, `decode("utf-8","ignore")` drops it. Uncut lone surrogates stay and fail at the jsonb stage as DataError, which the
existing bisect already handles. 4-byte characters (200 emoji) cut on a boundary (500 bytes = 125 characters, exact); combining
sequences cut leave a base character (valid text). Verified by direct calls.
