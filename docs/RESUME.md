## 4. Standing rules (learned the hard way)
1. **Worktrees.** Other sessions switch the shared folder's checked-out branch under you. Always work in your own worktree: `git fetch`, then `git worktree add -b <name> .worktrees/<name> origin/main`. `.worktrees/` is git-ignored. `git worktree list` shows many from earlier work; ignore them.
2. **CI runs only on pushes to `main` and on pull requests.** A pushed branch gets no CI. So: review and test the branch locally, fast-forward it to `main`, push `main`, then read CI there with `gh run list` and `gh run view`. The repo token cannot merge PRs. There is no branch protection yet (issue #44, owner action), so never force-push `main`.
3. **Deploy only on the owner's explicit go.** The permission system may also block production deploys until the owner approves; do not work around a denied action, report it. A deploy restarts the collector (about 45 s of snapshots).
4. **VM containers are capped.** Every throwaway container on the live VM needs `--memory` and `--memory-swap` caps (for example 512m), a CPU cap and a timeout, and you check `free -m` before and after. Incident 08-10-2026 (T39, issues #59 and #60): an unbounded test container took 6.9 GB of the VM's 7.9 GB and cost the live collector a 90 s gap.
5. **Never run `db/roles.sql` on the live cluster.** Roles are cluster-wide; running it with throwaway passwords resets the live role passwords. It is safe only in a throwaway container with its own cluster. Integration tests TRUNCATE tables and refuse to run unless the database name ends in `_test`.
6. **The deploy procedure and its traps are in one place: docs/RUNBOOKS/deploy-to-vm.md.** In short: fresh dump (`docker compose exec backup backup.sh once`), a copy of the VM tree for rollback, `timedatectl` clock check, `git archive --format=tar HEAD | ssh vatpac-v3 'cd ~/vatpac-statsV2 && tar -x'` (tar never deletes: remove files that were deleted or renamed in git by hand; `.env` is not in git), `docker compose stop collector`, then `docker compose up -d --build` (migrations run first through the migrate service; never `restart collector`, never `up -d` without `--build` for a collector change), then `sh ops/smoke.sh`, `python3 ops/check_panels.py` (expect 0 errors), restart counts 0, the `/health` archive block, and `ops/check_identity_flap.sql` (three zeros). The special cases are section 4b (fresh dump before the logon_time migration), 4c (stop-then-build, clock check, archive check) and 4d (the Dependabot image bumps: db container recreated, Grafana volume upgraded in place, backup image tag must equal the db tag).
7. **Do not hand the owner work Claude can do.** Do not run an action the permission system denied; surface it.
