# Tests

Written from `SPEC.md` (sections 4, 5, 6, 7, 11), not from the collector source.

| Where | What | Needs |
|---|---|---|
| `collector/tests/unit/` | filters, parsing, caps, frequency, `home_icao`, settings, golden filter test, fixture integrity | Python only (no network, no database) |
| `tests/integration/` | schema constraints, idempotent ingest, upserts and events, partitions, `flight` view, `grafana_ro` | a migrated PostgreSQL 16 (run on 07-10-2026: 94 passed, 1 skipped) |
| `tests/fixtures/` | anonymised feed snapshot and golden expectations | generated by `tests/tools/make_fixture.py` |

## Unit tests

```powershell
python -m venv collector/.venv            # or tests/.venv (both are git-ignored)
collector/.venv/Scripts/pip install pytest shapely pydantic-settings httpx "psycopg[binary]"
collector/.venv/Scripts/python -m pytest collector/tests/unit -q
```

Linux/macOS: `collector/.venv/bin/python -m pytest collector/tests/unit -q`. The suite adds
`collector/src` to `sys.path` itself, so an editable install is optional.

## Integration tests

Run against a real PostgreSQL 16.4 on 07-10-2026: 94 passed, 1 skipped. They are skipped unless
`VATPAC_TEST_DSN` is set.

1. Start a **throwaway** Postgres, create a database whose name ends in `_test`, and apply every file in
   `db/migrations/` in order, then `db/roles.sql`. The fixtures `TRUNCATE` every data table and drop
   leftover `pilot_position_*` partitions. (Override the name check only with
   `VATPAC_TEST_ALLOW_TRUNCATE=1`.) For example:

```bash
docker run -d --name vp-sqltest -p 127.0.0.1:55433:5432 -e POSTGRES_PASSWORD=sqltest postgres:16.4-bookworm
docker exec vp-sqltest psql -U postgres -c "CREATE DATABASE vatpac_test"
for f in db/migrations/*.sql; do docker exec -i vp-sqltest psql -U postgres -d vatpac_test -v ON_ERROR_STOP=1 -q < "$f"; done
docker exec -i vp-sqltest psql -U postgres -d vatpac_test -v ON_ERROR_STOP=1 -v grafana_ro_password=testpw -q < db/roles.sql
```

2. Run (adjust the port and passwords to match):

```powershell
$env:VATPAC_TEST_DSN = "postgresql://vatpac:<password>@127.0.0.1:55432/vatpac_test"   # dev profile port
# optional: connect as grafana_ro directly instead of SET ROLE
$env:VATPAC_TEST_GRAFANA_RO_DSN = "postgresql://grafana_ro:<password>@127.0.0.1:55432/vatpac_test"
collector/.venv/Scripts/python -m pytest tests/integration -m integration -q
```

The connecting user needs enough rights to create partitions and (for the `SET ROLE` fallback) to
`SET ROLE grafana_ro`; the owner/superuser of the test database is fine.

### Known assumptions (check first if something fails)

- `vatpac.store.apply_snapshot` commits its own transaction (or runs inside `conn.transaction()`); the
  tests use an autocommit connection.
- Partitions are created by the tests themselves (`CREATE TABLE ... PARTITION OF`), because SPEC s7 does
  not name the `vatpac.maintenance` functions. `test_partitions.py` part B looks for
  `ensure_partitions` / `drop_old_partitions` and skips if absent.
- The `flight` view exposes `cid`, `departure`, `arrival`, `sample_count`, `airborne_minutes`,
  `is_circuit`, `is_zzzz`, `touches_home_region` (SPEC s6 lists the flags and measures but not the
  complete column set). If it is a materialized view the tests `REFRESH` it first.
- Replaying a snapshot is judged on the data tables (not `poll_log`, which legitimately gets a row per
  attempt).
- `controller_unlisted_sighting` is expected to be filled during `apply_snapshot`; the test skips if the
  table stays empty.

## The fixture

`tests/fixtures/vatsim-data.sample.json` is one live snapshot (07-10-2026, `update_timestamp`
`2026-10-07T16:11:19Z`) reduced to 62 pilots, 23 controllers and 5 ATIS entries, then anonymised
deterministically:

- every `name` becomes `Pilot NNNN` / `Controller NNNN` (a trailing 4-letter ICAO token is kept);
- every `cid` becomes a number in 9000000..9999999 (seeded permutation, not reversible);
- remarks become `RMK/TEST`; ATIS text and controller free text are dropped; `prefiles` and `servers`
  are emptied;
- callsigns and positions are kept.

Hand-crafted entries are marked: pilot callsigns start with `TEST` (edge, vertex, implausible values,
missing position, missing plan, empty arrival, ...). Synthetic controllers must carry real whitelisted
callsigns, so they are listed in `expected.json` under `synthetic_controllers`.

`tests/fixtures/expected.json` holds the golden numbers and is generated by the same script using its
own shapely/whitelist implementation of the SPEC rules.

Regenerate (the raw snapshot is kept outside the repository and must never be committed):

```powershell
curl.exe -s https://data.vatsim.net/v3/vatsim-data.json -o $env:TEMP\raw_feed.json
tests/.venv/Scripts/python tests/tools/make_fixture.py --raw $env:TEMP\raw_feed.json --verify
```

`--verify` proves that no original name or CID survives (it prints counts only, never values). A CI PII
check can reuse the same patterns: names must match `^(Pilot|Controller) \d{4}( [A-Z]{4})?$`, CIDs must
be 9000000..9999999, remarks must be `RMK/TEST`.
