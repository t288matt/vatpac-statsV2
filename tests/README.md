# Tests

The first tests were written from `SPEC.md` (sections 4, 5, 6, 7, 11), not from the collector source; later ones (the `t14`, `card`, `online_hours`, `controller_retention` files) execute the SQL of the provisioned dashboard panels against synthetic rows. Counts are not quoted here (they go stale); see docs/RUNBOOKS/run-tests.md section 4.

| Where | What | Needs |
|---|---|---|
| `collector/tests/unit/` | filters, parsing, caps, frequency, `home_icao`, settings, robustness, golden filter test, fixture integrity | Python only (no network, no database) |
| `tests/integration/` | schema constraints, idempotent ingest, upserts and events, partitions, `flight_summary` and the `flight` view, poison records, `grafana_ro` and the other roles, and the panel SQL of the re-checked v1 cards (ATC, events, pilots, card 90, online hours, controller retention) | a migrated PostgreSQL 16 in a throwaway `*_test` database; `test_roles.py` and `test_grafana_ro.py` also need the roles from `db/roles.sql` |
| `tests/fixtures/` | anonymised feed snapshot and golden expectations | generated by `tests/tools/make_fixture.py` |

The runbook [docs/RUNBOOKS/run-tests.md](../docs/RUNBOOKS/run-tests.md) gives the commands to run everything, including the safe method on the VM. Counts are not quoted here because they go stale; the runbook (section 4) shows how to print the current ones. CI runs every file; the VM safe method excludes the role files (the runbook says why).

## Unit tests

```powershell
python -m venv collector/.venv            # or tests/.venv (both are git-ignored)
collector/.venv/Scripts/pip install pytest -r collector/requirements.txt
collector/.venv/Scripts/python -m pytest collector/tests/unit -q
```

Linux/macOS: `collector/.venv/bin/python -m pytest collector/tests/unit -q`. The suite adds
`collector/src` to `sys.path` itself, so an editable install is optional. CI and `make test` run the wider
command `PYTHONPATH=collector/src pytest -q -m "not integration" tests collector/tests --ignore=tests/.venv`.

## Integration tests

They are skipped unless `VATPAC_TEST_DSN` is set; with `VATPAC_TEST_STRICT=1` (CI) a missing DSN aborts the run and any skipped test fails it (runbook section 5).

1. Start a **throwaway** Postgres 16, create a database whose name ends in `_test`, apply every file in
   `db/migrations/` in order (the `-- migrate:up` half; `sed '/^-- migrate:down/,$d' file` drops the rest, as dbmate does), then `db/roles.sql` with all three password variables. The fixtures `TRUNCATE` every data table and drop
   leftover `pilot_position_*` partitions, so the name check is a safety net. (Override it only with
   `VATPAC_TEST_ALLOW_TRUNCATE=1`, and never on the live database.) For example:

```bash
docker run -d --name vp-sqltest -p 127.0.0.1:55433:5432 -e POSTGRES_PASSWORD=sqltest postgres:16.4-bookworm
docker exec vp-sqltest psql -U postgres -c "CREATE DATABASE vatpac_test"
for f in db/migrations/*.sql; do sed '/^-- migrate:down/,$d' "$f" | docker exec -i vp-sqltest psql -U postgres -d vatpac_test -v ON_ERROR_STOP=1 -q; done
docker exec -i vp-sqltest psql -U postgres -d vatpac_test -v ON_ERROR_STOP=1 -v grafana_ro_password=testpw -v collector_password=cpw -v backup_password=bpw -q < db/roles.sql
```

   Never run `db/roles.sql` against the live VM or the stack's own Postgres container: roles are cluster-wide
   and it resets the live role passwords.

2. Run (adjust the port and passwords to match):

```powershell
$env:VATPAC_TEST_DSN = "postgresql://postgres:sqltest@127.0.0.1:55433/vatpac_test"
# optional: connect as grafana_ro directly instead of SET ROLE
$env:VATPAC_TEST_GRAFANA_RO_DSN = "postgresql://grafana_ro:testpw@127.0.0.1:55433/vatpac_test"
collector/.venv/Scripts/python -m pytest tests/integration -m integration -q
```

The connecting user needs enough rights to create partitions and (for the `SET ROLE` fallback) to
`SET ROLE grafana_ro`; the owner/superuser of the test database is fine.

### Known assumptions (check first if something fails)

- `vatpac.store.apply_snapshot` commits its own transaction (or runs inside `conn.transaction()`); the
  tests use an autocommit connection.
- Partitions are mostly created by the tests themselves (`CREATE TABLE ... PARTITION OF`);
  `test_partitions.py` also exercises `vatpac.maintenance.ensure_partitions` and `drop_old_partitions`
  (imported directly, so a rename fails the test).
- Replaying a snapshot is judged on the data tables (not `poll_log`, which legitimately gets a row per
  attempt).
- Role tests (`test_roles.py`, `test_grafana_ro.py`, the role tests in `test_watchdog_flap.py`) skip with a stated
  reason when a role has not been created; in strict mode that fails the run. No other integration test skips.
- Shared helpers live in `tests/integration/helpers.py`; the `conn` fixture restores `app_setting` after each test.
- Panels that read `now()` are run with a clock seam where a date matters (`run_panel(..., now=...)` in
  `test_military_events_t15.py`): the text `now()` in the panel SQL is replaced by a fixed instant.

## The fixture

`tests/fixtures/vatsim-data.sample.json` is one live snapshot (07-10-2026, `update_timestamp`
`2026-10-07T16:11:19Z`) reduced to 62 pilots, 23 controllers and 5 ATIS entries, then anonymised
deterministically:

- every `name` becomes `Pilot NNNN` / `Controller NNNN` (a trailing 4-letter ICAO token is kept);
- every `cid` becomes a number in 9000000..9999999 (seeded permutation, not reversible);
- remarks become `RMK/TEST`; ATIS text and controller free text are dropped; `prefiles` and `servers`
  are emptied;
- callsigns and positions are kept.

Hand-crafted entries are marked: pilot callsigns start with `TEST` (edge, vertex, implausible values,
missing position, missing plan, empty arrival, ...). Synthetic controllers must carry real whitelisted
callsigns, so they are listed in `expected.json` under `synthetic_controllers`.

`tests/fixtures/expected.json` holds the golden numbers and is generated by the same script using its
own shapely/whitelist implementation of the SPEC rules.

Regenerate (the raw snapshot is kept outside the repository and must never be committed):

```powershell
curl.exe -s https://data.vatsim.net/v3/vatsim-data.json -o $env:TEMP\raw_feed.json
tests/.venv/Scripts/python tests/tools/make_fixture.py --raw $env:TEMP\raw_feed.json --verify
```

`--verify` proves that no original name or CID survives (it prints counts only, never values). The fixture is anonymised by construction: names look like `Pilot 0001` or `Controller 0001`, CIDs are 9000000..9999999 and remarks are `RMK/TEST`.
The CI check that enforced this (`ops/check_fixture_pii.py`, `make pii`) was removed on 08-10-2026 (owner decision: names and CIDs are public, ADR-019), so new fixtures may hold real names and CIDs; the anonymised one stays as it is.
